# MLR Review — hard rules (canonical numbering)

This is the one canonical list. Every `SKILL.md` "Hard rules (every MLR skill)" section, the tools (`tools/runtime.py` cites MLR-H5 for `cleared_by`) and every other file use these ids. Skill folders point here; they do not keep their own numbered copy.

- **MLR-H1.** Only stored material counts — fields from the person or a tool result.
- **MLR-H2.** Teaching material is never input — examples/ and patterns.md are invented for shape.
- **MLR-H3.** Never approve — no approved-for-use, mlr_reviewed, or regulator-compliant stamp.
- **MLR-H4.** Never simulate the connector — without vmlr_/vvfy_ label not tool-checked.
- **MLR-H5.** A named human owns prep records — refuse ai/model/assistant/system as cleared_by.
- **MLR-H6.** Markets explicit — never default jurisdictions to the US.
- **MLR-H7.** Keep M / L / R MECE — do not blend chairs or substitute another market's rules.
- **MLR-H8.** Plain liability — every user-facing result ends with the closing line.

## Detail per rule

Carried over unchanged in meaning from the former `mlr-capability-map/references/hard-rules.md`, which used a different numbering (former id in brackets).

| MLR-H1 | Never create stand-in packets, placeholder versions, or chair decisions to make a tool run (TEH-RDY-017). Run tools on artefact text only when the person supplied that text: when only a description exists, reason from the description, say "no artefact text was supplied", and present no tool output — never build a body, claim list or ISI block from the description to feed a tool (TEH-RDY-021). The person's own description is person-supplied material: when the person describes a mismatch (for example what the body says against what the label says) without supplying the file, a finding may be opened on that description — the finding quotes it as the person's description (`Person's description: "…"`), carries the label `based on the person's description — verify against the artefact`, keeps the claim span and any label text it lacks as `[GAP]`, and takes its status from the precedence order like any other finding; a description never becomes artefact text, label text, a locator, a claim span, a tool input or a packet (TEH-RDY-035). Call a tool only with field values the person supplied or an earlier tool returned: leave a missing field empty so the tool reports it in `missing_fields`, and never pass a placeholder, an example value or a guessed value (for example an artefact version the person did not give) (TEH-RDY-028). A claim span is a verbatim quote from text the person supplied (artefact text, or a phrase the person quoted); when no artefact text was supplied the claim span is `[GAP]`, never a phrase composed from the request (TEH-RDY-026). Every cited rule id must exist in a ruleset loaded for this packet (`rulesets/*.json`) and its row's check must cover the concern; never mint a rule id — with no matching row, write `[GAP] no matching rule row` or route the concern (TEH-RDY-025). Open a finding only on an issue present in the supplied text or described by the person; a hypothetical risk is a `Watch for:` note, never a finding (TEH-RDY-048). |
| MLR-H3 | Never approve, clear, or mark copy compliant / `mlr_reviewed` [former H1]. Company SOP and committee outrank this pack; name the SOP when supplied [former H7]. |
| MLR-H4 | Claim/source passage checks stay on VERIFY (`vvfy_`); mark **not tool-checked** without it [former H6]. Without `vmlr_`, method may run but tool results are **not tool-checked** — never invent validation [former H9]. A request to write, save or record anything to a connector without a valid key is a bypass request (precedence rule 1, `human_gate_required`; TEH-RDY-044). |
| MLR-H5 | Full refusal token list: `skills/mlr-board-prep/SKILL.md` § Tool path; enforced by `cleared_by_refusal()` in `tools/runtime.py`. |
| MLR-H6 | Markets must be explicit in `jurisdictions[]` — no US (or other) default [former H2]. No markets menu: When the person has named no markets: ask for them, and do not list, enumerate or suggest any specific jurisdiction (not from the ruleset registry, not as "for reference"). Say only that rule packs exist and will be listed once the person names markets. Do not call `mlr_list_rulesets` / `mlr_get_ruleset` until markets are named (TEH-RDY-015). Per supplied market: every market-scoped line (label basis, ruleset coverage, standards touched, `applies_to`, residuals) has one entry per market the person supplied and none for any other market; never copy a market list from a reference, template or example (TEH-RDY-024). A label-basis line names the supplied market's own label document from `references/label-basis-by-market.md` (a market not listed there: "authorized labeling for <market>"); never another market's document name and never an "X or Y" list of document names (TEH-RDY-038). Rule pack binds only on supplied context: no `ruleset_id` is named, bound or reported with coverage until markets, audience and channel are all person-supplied (or explicitly derived from supplied evidence, said so); until then write "rule pack binds once audience and channel are supplied"; tools receive only supplied values (TEH-RDY-043). Channel means the communication intent the rule-pack catalogue keys on (`promo`, `scientific_exchange`); the delivery medium (email, print, digital display, congress, social) is recorded and never binds a pack or counts as an unrecognized channel; intent words are mapped transparently and reported (TEH-RDY-057). This rule never stops acknowledging a pack, coverage label or residual the person or packet names, or reporting catalog coverage from `rulesets/REGISTRY.json` for a supplied market (TEH-RDY-060). Ask for markets before any market-dependent step, including when routing to intake on a refusal path (TEH-RDY-045). Echo markets exactly: when an answer restates the markets the person named, it repeats the supplied list exactly — every supplied market and no other; never "only <one market>" when more were supplied (TEH-RDY-042). Form 2253: name it only when US is a supplied market or the person asks about it, and then only as the line `[DEFERRED] Form 2253 — out of READY scope`, never as a finding, rule row or rule id; otherwise write "regulator submission filings are deferred" (TEH-RDY-025, TEH-RDY-031). |
| MLR-H7 | Medical, Legal, and Regulatory are separate chairs with MECE ownership [former H3]. Do not substitute another market's full ruleset for a stub or missing pack [former H4]. Authorized use is per market: one market's labeling never substitutes for another's, and each market's label document is named from `references/label-basis-by-market.md` (TEH-RDY-038) [former H5]. |
| MLR-H8 | Every user-facing summary ends with the liability line [former H8]. |
