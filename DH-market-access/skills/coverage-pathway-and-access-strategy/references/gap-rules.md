# Gap rules

A gap is information, not an apology. The person needs to know *why* something is missing, because each reason leads to a different next step.

## Four kinds of result per scheme

| Class | When | How to word it | Next step for the person |
|---|---|---|---|
| Found | The product has a status row. | State status, plain meaning, date. | None. |
| Field missing | The row exists but a field (end date, price, history) is empty. | "Listed; the source does not state an end date `[GAP]`." | Check the authority's page for that field. |
| Covered, product absent | The scheme has listings in the library (`listing_count` > 0) but none for this product. | "Not in the library's copy of this scheme (N listings, loaded DATE, posture P)." | Check the authority directly before concluding. If posture is `partial`, say the copy may be incomplete. |
| Not covered | The scheme has no listings in the library (`listing_count` 0, posture `gap`). | "The library holds no listings for this scheme: REASON." | The library cannot answer here; check the authority. |

## Never

- Never turn any of these into "not reimbursed", "no coverage", or "denied".
- Never pass through the report tool's flat "checked, none loaded [GAP]" line. It is used for both of the last two classes and reads as wrong to a buyer when the scheme does hold listings.
- Never fill a gap from memory or from a guidance passage that has no source URL.
