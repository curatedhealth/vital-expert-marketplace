# Gap rules

A gap is information. Each reason for a gap leads to a different next step, so name the reason.

## Requirement and method facts

| Class | When | How to word it | Next step |
|---|---|---|---|
| Sourced | A research row states it. | The fact plus the row id (for example "training knowledge can decay over time, CS78"). | None. |
| Read by a summarizer | The row is marked [WF] (DTAC, DCB0160: CS69 to CS71). | The fact, the row, and "read through a summarizing fetch; re-check the page before relying on it". | Re-read the source page. |
| Clause text paywalled | ISO 14971 or IEC 62366-1 clause text. | "Clause text not public in this skill's sources `[GAP]`; abstract only (CS81, UX-STD-36)." | The person's licensed copy. |
| Market not in the research | A training duty for a US or EU deploying customer other than HIPAA workforce training. | "No training-plan requirement for this market in this skill's sources `[GAP]`." | Ask the customer's owner or the regulatory owner. |
| Strategy not quoted | An ERIC strategy the person names that is not in `enablement-strategies.md`. | "ERIC strategy name; definition not in this skill's sources `[GAP]`." | Read the ERIC paper (DOI 10.1186/s13012-015-0209-1). |
| No effect data | Any claim that a strategy improves adoption by an amount. | "No effect size in this skill's sources `[GAP]`." | A published study, checked through Verify with a results passage. |

## The person's facts

| Situation | How to word it |
|---|---|
| Role or task not stated | Ask. Without the task card there is no session record and no completion count. |
| Day-one workflow not described | "Workflow not described `[GAP]`"; ask the person or the site's implementation lead they name. |
| Whether the product is a device not stated | "Device status not stated `[GAP]`"; the human factors rows apply only if it is one; ask the regulatory owner. |
| Validated training content not available (device) | "Validated training not seen `[GAP]`"; customer training should match it (CS80). |
| No owner named | Use the owner or role the person names, in their words. Only if they named none, write "owner not named" and ask. Never suggest a job title. |
| No check window or share | Leave it blank and ask; never pick a number of days or a share. |
| Completion not recorded in the log | "Completion not recorded"; count it apart from "attended, not completed". Never count it as done. |
| Evidence described but not shown | "Described, not seen." |
| No scores for B1 | No ranking. Lay out the facts per option and ask the person to score. |

## Library facts

| Situation | How to word it |
|---|---|
| No safety events returned | "No events in the library for this query; absence is not evidence of no events." |
| `check_claim` "supported" | Accept only after reading the passage and confirming the same direction, numerator and denominator (register N3). |
| `check_claim` "unverifiable" on an FDA, NICE or statute rule | Expected (register C1). Cite the row. |

## Never

- Never fill a training requirement, a number of hours, a retention rate, an owner, a score or a window from memory.
- Never treat a missing row as "not required".
- Never treat full attendance as evidence that people can do the task.
