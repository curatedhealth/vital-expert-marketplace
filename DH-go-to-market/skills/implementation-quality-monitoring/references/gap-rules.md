# Gap rules

A gap is information. Each reason for a gap leads to a different next step, so name the reason.

## Definitions and requirements

| Class | When | How to word it | Next step |
|---|---|---|---|
| Sourced | A research row defines it. | The definition plus the row id (for example "penetration, eligible users who use it over all eligible, CS39"). | None. |
| Two definitions | The term has more than one sourced definition (adoption, reach and penetration). | Name the one used and its row. | None. |
| No threshold | The person asks whether a number is good. | "The source defines the measure, not a level (CS31); the threshold is yours." | Ask for their rule. |
| Summarizer read [WF] | A bar item rests on CS69, CS70 or CS71. | Add "(read through a summarizer, [WF])". | Re-check the page before relying on it outside the conversation. |
| Not sourced | Customer health, renewal, churn, NRR, time-to-value. | "Not sourced; these rules are yours (research file, Not sourced)." | Customer Health (DH-02.02.3.x) or the person's own definitions. |

## The person's data

| Situation | How to word it |
|---|---|
| A column is blank | "Not measured `[GAP]`", and name the record that would hold it (for example the eligible-patient count from the site's registry). |
| Active exceeds eligible, or delivering exceeds expected | "Check the denominator" (the script flags it); do not report the ratio as a finding until resolved. |
| No baseline date | The milestone is not counted for fidelity or slippage `[GAP]`. |
| No as-of date | Use the date of the conversation and say so. |
| No bar for a site | No deployment check; offer the planning skill's starting list. |
| Evidence described but not shown | "Described, not seen." |
| No pass rule or target | Report the number; no verdict. |
| No owner | Use the owner or role the person names, in their words. Only if they named none, write 'owner not named' and ask. Never suggest a job title. |
| No recheck date | Leave it blank and ask; never pick a date. |
| No scores for repairs | No ranking. Lay out the facts per repair and ask the person to score. |

## Library facts

| Situation | How to word it |
|---|---|
| No safety events returned | "No events in the library for this query; absence is not evidence of no events." |
| `check_claim` returns "supported" | Accept only if the passage read states the claim in the same direction (register N3). |
| Library returns 502 or 503 | Retry once; then "the library did not answer; nothing was counted". |

## Never

- Fill a count, date, owner, score or target from memory.
- Treat no evidence, no events or no complaints as success.
