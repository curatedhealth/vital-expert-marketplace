# Gap rules

A gap is information. The person needs to know why something is missing, because each reason leads to a different next step.

## Regulatory rules

| Class | When | How to word it | Next step |
|---|---|---|---|
| Sourced | A row in `references/` states it | The rule in plain words, with its row id | None |
| Standard text not sourced | The rule sits in ISO 13485, ISO 14971 or IEC 62304 clause text | "Clause 4.2.5 sets this; its text is not in the sourced references `[GAP]`." | Read the clause through the free ANSI IBR portal or ISO OBP (ST13) |
| Guidance not sourced | A rule from guidance not read in the research (for example FDA's general 510(k) change guidance, PMA supplement rules, UK change rules) | "Not covered by the sourced references `[GAP]`." | The owner checks the regulator's page |
| Out of scope of the guidance | The framework does not apply (PMA or exempt device for the 2017 guidance; MDR-certified device for MDCG 2020-3) | Say so and name the framework that applies, or `[GAP]` | Walk the right framework |
| Draft or superseded | Guidance is draft, or a newer version exists | State status and date | Use the current version |

## Library facts

| Class | When | How to word it |
|---|---|---|
| Found | The record exists | Fields as stated, with source URL and retrieval date |
| Field missing | The record exists, the field does not (PCCP authorized, change history) | "The record does not state whether a PCCP was authorized `[GAP]`." Ask the person |
| Not in store | No match | "The library holds no record matching X; this is a gap in the store, not evidence the device is unauthorized." |
| Not loaded | The jurisdiction holds no data (UK registrations, CH) | "The library holds no data for X." |

## The person's change

| Situation | How to word it |
|---|---|
| A question the person has not answered | "Not answered `[GAP]`"; the question stays open and the sheet is incomplete |
| The person answered without a basis | Record the answer and "basis not given"; ask for the risk file reference or test report |
| Answers conflict (for example "bug fix" but a new hazard in the risk file) | Quote both and ask the owner to resolve before any conclusion |

## Never

- Never turn a gap into "no submission needed", "not significant" or "compliant".
- Never fill a gap from memory, including ISO clause text and retention periods.
