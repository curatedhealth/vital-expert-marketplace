# Readiness requirements for AI-enabled device software

Interpretive reference for task A1 and B1. Row prefixes: `AI` = `AI_ML_REGULATION.md`, `RP` = `REG_PATHWAYS_SUBMISSIONS.md`, `Q` = `QUALITY_SYSTEMS.md` (all read 19 October 2026). Each item is a **presence check**: does the person's package contain it? Whether it is adequate is the person's judgment. "Applies" depends on the person's route, class and dates; the model states the condition, the person confirms it applies.

Status words used in the check: **present** (the person shows it or names where it is), **missing**, **not yet applicable** (with the date it starts), **not assessable** (the person has not said), **not in references** `[GAP]`.

**Legacy devices.** A high-risk AI device placed on the market before its Chapter III date is caught only if it then undergoes significant changes in design [AI EU-22]. For MDD legacy devices, MDCG 2020-3 Rev.1 (May 2023) sets the two cumulative tests for a significant change, with software chart C [Q CH3 to CH8]. What counts as significant under the AI Act is not in the references `[GAP]`.

**Superseded dates.** MDCG 2025-6 still says 2 August 2027 for Annex I systems; the date in force is 2 August 2028 [AI EU-32, EU-19]. Flag any file, plan or vendor statement that uses 2 August 2027 or 2 August 2026 for a device.
