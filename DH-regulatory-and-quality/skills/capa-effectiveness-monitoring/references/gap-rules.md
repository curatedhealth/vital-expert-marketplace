# Gap rules

A gap tells the person what is missing and why, because each reason leads to a different next step.

## The person's records

| Situation | How to word it | Next step |
|---|---|---|
| No effectiveness criterion in the CAPA plan | "No effectiveness criterion was set for this action `[GAP]`; it cannot be checked." | Back to the CAPA plan (sibling skill, B1) |
| Criterion set, evidence not supplied | "Evidence not supplied: [record named in the criterion]." Status "evidence missing", not "fail" or "pass" | Ask for the record |
| Window not over | "Window runs to DATE; check not yet due." | Wait or check interim, as the person decides |
| Complaint without awareness date | "No awareness date recorded: clock cannot be computed." | Ask; the US event file needs it (VG21) |
| Complaint code missing or inconsistent | "Code not recorded `[GAP]`; recurrence cannot be matched." | The person codes it |
| No ageing limit, no pass rule, no owner | "No limit set by you"; "no rule set"; "owner not named" | Ask; never suggest a number or a job title |

## Regulatory and public context

| Situation | How to word it |
|---|---|
| Rule in a sourced row | State it with its row id |
| No sourced rule (effectiveness test, window length, GB day counting, root cause method) | "Not in the sourced rules `[GAP]`." |
| 483 data used | "FDA FY 2025 data, pre-QMSR, not a complete list, not a benchmark" |
| No safety events returned | "No stored events for this search; absence is not evidence that none occurred." |

## Never

- Never turn a gap into "effective", "closed", "no recurrence" or "on time".
- Never treat a missing check as a pass. A check not performed is a fail by the register rule, and the output says why.
- Never fill a gap from memory or a passage without a source URL.
