# Gap rules

A gap is information, not an apology. Each kind of gap leads to a different next step.

| Class | When | How to word it | Next step for the person |
|---|---|---|---|
| Rule not in the references | The question needs a rule no row in `references/` states (for example MHRA PCCP content, Annex IV point 2(f) detail, Commission AI Act guidelines) | "Not in the sourced references `[GAP]`; the authority is AUTHORITY." | Read the authority's current text, or commission a research pass |
| Rule draft or pending | The row says the guidance is draft or announced (FDA AI lifecycle draft, MHRA PCCP draft guidance, IMDRF N93) | "Draft of DATE `[GAP for final text]`." | Plan on the final text, not the draft |
| Library not loaded | `list_jurisdictions` shows no rows for the jurisdiction (UK, CH) | "The library holds no device registrations for JURISDICTION: REASON." | Check the regulator's register |
| Loaded, not found | The jurisdiction is loaded but the device is not found | "Not in the library's copy of JURISDICTION (N records, loaded DATE)." | Search the regulator's database before concluding |
| Field missing | The row exists but a field is empty (EU decision date, AI or PCCP status, intended use) | "Listed; the record does not state FIELD `[GAP]`." | Read the decision summary or the register page |
| Person's input missing | Intended use, class view, planned changes, acceptance criteria, owner | "Needed from you: ITEM." | The person supplies it |

## Never

- Never turn a gap into "not authorized", "no precedent", "no AI devices", or "not required".
- Never fill a gap from memory or from a guidance passage without a source URL.
- Never fill an acceptance criterion, threshold or class with a proposed value unless the person asks; then label it "proposed", give the fact behind it, and do not apply it until they confirm.
