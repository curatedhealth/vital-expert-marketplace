# Failure-mode library (screen every package against every mode)

Each mode: id, what goes wrong, detection question, where documented, source, passage ids, status. A failure mode is a published pattern, not a verdict on any asset. Status as in method-standards.md (VERIFIED-REOPENED requires a registered passage). The detection questions are written for this skill and are labeled ENGINEERING RULE in grounding-register.md; the finding in each row is the sourced part.

| Id | Mode | Detection question (answer: triggered / not triggered / cannot tell) | Documented for | Source and finding | Passage ids | Status |

## Notes
- Hwang et al., JAMA Intern Med 2016 (reasons for phase 3 failure; 640 novel therapeutics): abstract only, full text paywalled; not used in any row.
- FM-08 is the one mode without a registered primary passage (trade press only, SUMMARY-ONLY); the screen still asks its detection question, and the row is never scored. FM-04 is re-registered from the NLM copy of the OIG report (VP-A-160 to VP-A-163).
- Hwang et al., JAMA Intern Med 2016 (P7): the file could not be opened as readable text (the host serves a download and the publisher copy is not open); not relied on.
- Failure modes for the other workstreams (peak-sales overestimation, reimbursement, patent invalidity, inherited licensor obligations, data-room integrity, overpayment and impairment) are in their own skills.
