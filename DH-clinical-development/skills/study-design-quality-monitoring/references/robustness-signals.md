# Robustness signals

Interpretive reference for A2 and B1. A signal is a fact worth the person's attention, never a verdict. Each carries the row that makes it a signal. The person decides which signals become pass rules and how strict each is.

## Registration and consistency signals

| Signal | Why it matters (row) |
|---|---|
| First submitted to the registry after the first consent (or after the start date, when consent date is unknown) | ICMJE prospective registration (CV132) |
| More than 21 days between first enrollment and registration, for an applicable clinical trial | 42 CFR 11.24 (CV141) |
| Registered primary outcome worded differently from the protocol or the paper, especially the analysis metric (for example a count versus time to event) or the time point | Outcome specification (SP-16, CV113); changes must be reported with reasons (CV114) |
| Secondary outcomes in the paper not in the registry, or the reverse | Selection of the reported result is a RoB 2 domain (ES-71) |
| Masking in the registry differs from the protocol | Blinding items (SP-24a) |
| No results posted more than one year after primary completion, for an applicable trial with no certification shown | 42 CFR 11.44 (CV145, CV146) |
| Registration not updated within 12 months, for an applicable trial | 42 CFR 11.64 (CV149) |
| No data sharing plan in a registration of a trial enrolling from 1 January 2019 | ICMJE (CV135, CV136) |

## Design signals

| Signal | Why it matters (row) |
|---|---|
| No primary estimand, or estimator and sensitivity analysis not prespecified | E9(R1) A.6 (CV40) |
| Missing data handling not tied to an estimand | CV41 |
| Participants choose site or remote assessment | Can bias results (CV67) |
| Different data collection methods across arms | CV58 |
| Non-inferiority with a DHT measure and no comparator effect measured the same way | CV58, CV72 |
| DHT endpoint without V&V in the study population, or only in healthy volunteers | CV46, CV48 |
| No usability evaluation of the DHT in the trial population | CV51 |
| Own-device participation without a sponsor-provided option | CV53 |
| No data flow description, no audit trail provision, or no contingency for tool malfunction on critical-to-quality elements | data flow (CV68, CV102); audit trail (CV14); contingency (CV99) |
| Participant-entered primary or safety data without measures against entry error | CV103 |
| AI intervention without algorithm version or performance-error plan | CV119, CV122 |
| Allocation concealment, blinding of outcome assessors or retention plans absent | RoB 2 domains (ES-71) as design checks; SP-22, SP-24a, SP-25b |
| Cited standards superseded (SPIRIT 2013, E6(R2), 2017 device RWE guidance) | CV115, CV2, CV88 |

## How signals are reported

- State the fact and its source ("Registry: 'Number of Participants With Major Depressive Disorder'; paper section 2.4: 'time to onset of MDD'").
- State the row that makes it a signal.
- Do not state a cause, an intent or a consequence beyond the row. "Differs; read the registry history and the protocol amendments" is the furthest the model goes.
- RoB 2 judgments are made per result, by reviewers, with signalling questions (ES-70, ES-72); this skill never gives one.
