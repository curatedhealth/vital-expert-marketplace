# Rules for Implementation plan

Pack: vital-decision-companion. Method version: 0.4.0. Content pack: 2026-10-29.1

- **R1.** Implementation waits for a recorded choice. The plan never chooses it.
- **R2.** One named owner. A role title is a gap until the person names who.
- **R3.** First milestone within 48 hours, in the person's words.
- **R4.** A review trigger is a condition. A date alone is a review date, not a trigger.
- **R5.** Each if–then plan has a signal, an owner, and an action. Vague actions are sent back to the person.
- **R6.** Each stored pre-mortem failure gets an if–then plan or an explicit "not given yet".
- **R7.** The connector completes implement on a decide name alone; list the plan fields still missing.

Hard rules DC-H1 through DC-H8 in `SKILL.md` still apply.

# Patterns for Implementation plan

Sources for the method: the Playbook Implement stage (Part 10: DAI-I planning questions, implementation template, quick wins); implementation intentions (Gollwitzer & Sheeran 2006, d = 0.65 over 94 tests); WRAP tripwires (Heath & Heath).

## Pattern 1

Person gives an owner and a date but no trigger. Ask what result would make them revisit before that date.

## Pattern 2

Pre-mortem says the vendor might miss the deadline. If-then: if the first deliverable is late by a week, then the owner escalates to the decider.

## Pattern 3

Person says the team owns it. Ask which one person is accountable.
