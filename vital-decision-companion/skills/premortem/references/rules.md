# Rules for Pre-mortem

Pack: vital-decision-companion. Method version: 0.3.6. Content pack: 2026-10-26.1

- **R1.** Ask for failure, early signal, mitigation, and owner. Leave a missing field as [GAP].
- **R2.** Store the list with decision_premortem. Do not rank the hypotheses.
- **R3.** Dig deep and full process require this list before the choice is treated as final.
- **R4.** A hypothesis the person regrets saying stays on the list.
- **R5.** The list does not set chosen_option.
- **R6.** Six months is the prompt. If the person names another horizon, use theirs.
- **R7.** In a group, reasons are written alone before they are shared, so the first speaker does not anchor the rest.
- **R8.** Keep raised_by with each hypothesis. Do not merge two people's failures into one line.
- **R9.** Each failure goes to implement-plan as an if–then plan or an explicit [GAP].

Hard rules DC-H1 through DC-H8 in `SKILL.md` still apply.
