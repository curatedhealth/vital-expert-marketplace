# Gap rules applied to fit for the reader

> **Where the marker belongs.** Use the `[GAP: …]` marker only inside a drafted deliverable. In notes, open-item lists and explanations, write the gap as a plain sentence ("Still missing: …, from …"). See `trusted-capability-map/references/gap-rules.md`.

Same format and classes as every TRUSTED skill:
`[GAP: <class> — <what is missing> — <what would close it>]`

| Class | Typical case in this skill |
|---|---|
| `not supplied` | A plain explanation needs a fact the material lacks (what a test measures, a frequency in numbers, the approved local term for an indication) |
| `needs a decision` | Which reader leads when two readers' needs conflict; what to drop when the content does not fit the format asked for; whether to adapt a translation for a new reader |
| `conflicting` | The original and a supplied approved local wording say different things; two supplied glossaries disagree on a term |
| `out of date or unclear date` | Supplied approved local wording or a glossary has no date or version |
| `not checkable here` | Rarely used: this skill has no companion. Use it only if the person asks whether a translation matches an approved text that was not supplied |

Wording rules:

- Name the exact item: "approved German wording for the side-effect term 'injection site
  reaction'", not "terminology".
- Never put a candidate translation or a candidate plain explanation inside a gap. If
  you offer one, label it outside the gap as unconfirmed.
- A gap in a patient text is written for the person who will fill it, not for the
  patient. It is removed before the text is used.
- A term flagged for a qualified translator is listed in the translation note, not
  scattered through the text as gaps, unless the person asks for inline flags.
