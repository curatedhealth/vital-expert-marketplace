# Task TR-1.2.2 Deliverable fit

## Formula

| Slot | For this task |
|---|---|
| Worker | Medical writer who has written for every audience |
| Workflow | Fix the format, length and structure that were asked for, fit the content into it, and say what did not fit |
| Skill | TR-1.2.2 |
| Knowledge | `references/patterns.md` (D1–D8), `references/readers.md` |
| Tool | None. Companion slot: none (no companion planned) |
| Prompt | This guide |
| Template | `assets/repair-note.md`, `assets/check-line.md`, the format table below |
| Input | The request (format, length, limit), the context card's deliverable line, the material, any existing draft |

## What was asked for

Read the format and length from the request or the context card. If the request names a
format with no length, use the usual shape below and say so in one line. If no format is
named and it changes the draft, ask once.

| Asked for | Usual shape, unless the person says otherwise |
|---|---|
| One-pager | One page: headline, three to five points, the ask or next step. Detail goes to an appendix only if the person wants one |
| Email | Subject that says what it is; the point or ask in the first two lines; short paragraphs; one clear next step |
| Slide | One message in the title; supporting points that prove it; the source line where figures appear |
| Memo | Purpose, background in brief, analysis, recommendation or options, next step |
| Reply (to a doctor, payer, colleague) | Answers the question that was asked, first, in the asker's terms; then only the context they need |
| Executive summary | Stands on its own; a reader who stops here has the finding, its limits and the ask |
| Key messages | Each message one or two sentences; no message that needs a paragraph to be true |

These are working shapes, not rules. A company template, when the person supplies one,
replaces them.

## Guard (while drafting)

1. **Set the frame before writing.** Format, length or limit, and the structure the
   format implies. Count against the limit as you draft, not after.
2. **Fit the content, not the format.** When the material is larger than the format,
   choose what this reader needs most (task TR-1.2.1) and say in one line what was left
   out and where it could go.
3. **No bait and switch.** Never deliver an essay, a report or a deck in place of the
   one-pager, email or slide that was asked for, and never answer a different question
   from the one in the request.
4. **Never cut the fact that changes the meaning.** A limitation, a comparator, a
   timepoint or a risk that the finding depends on stays in, even in one line. If the
   format cannot hold it, say so and ask.
5. **Respect a template.** When the person supplies a company template or format, use
   its sections and order; do not add an invented framework.

## Repair (existing draft)

1. **Compare the draft to the request:** format asked vs delivered; length or limit
   asked vs delivered (count words, pages or slides); the question asked vs the question
   answered.
2. **Reshape** into the format asked for. Move detail out, merge repeats, put the point
   first. Use `substance-and-usefulness` if the problem is filler rather than shape.
3. **List what was cut or moved** in the repair note. Never cut silently.
4. **If the content cannot fit** without losing a fact that changes the meaning, return
   the closest version and offer the person a choice: a longer format, an appendix, or
   which point to drop.

## Boundaries

- Structure inside a format (headings that say nothing, invented 2x2s) is
  `substance-and-usefulness`. This task owns the match between what was asked for and
  what was delivered.
- Typography, layout, brand templates and visual style are out of scope (TR-H9).
- A required statement that a market or process adds to a format (for example a
  prescribing information line on promotional material) is `market-rules-and-data`.
  This task never drops one to save space; it flags the space problem.
