# Output format: repair note

Follows the fixed text. Plain language, no rule codes (TR-H13). Size it to the stakes
(TR-H12): for an internal email, one or two lines; for anything leaving the company, the
full note.

## Full note

```
What I changed and why (draft, not yet reviewed)

Based on: <one line per thing you supplied>

Changed
1. "<before>" → "<after>". <Why, in one plain sentence, e.g. "Your notes give a forecast,
   not an actual figure.">
2. ...

Left as gaps for you to fill
1. <what is missing> — <where it would come from>

Questions for you
1. <a conflict or a choice only you can make>

<If the work leaves the company:> Next step: this goes through your <kind of internal
process, e.g. promotional review> before it is used.

I compared the draft with what you gave me; I did not check it against the original
sources with a tool.
```

## Short note (internal, low stakes)

```
Changed: <one line>. Gap left: <one line, if any>.
```
