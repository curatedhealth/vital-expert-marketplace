# Gap rules applied to confidence scoring

> **Where the marker belongs.** Use the `[GAP: …]` marker only inside a drafted deliverable. In notes, open-item lists and explanations, write the gap as a plain sentence ("Still missing: …, from …"). See `trusted-capability-map/references/gap-rules.md`.

Same format and classes as every TRUSTED skill:
`[GAP: <class> — <what is missing> — <what would close it>]`

| Class | Typical case in this skill |
|---|---|
| `not checkable here` | VERIFY is not connected, or did not run on these statements, so no confidence figure can be given: `[GAP: not checkable here — confidence figure — connect VERIFY and check each statement against its passage]` |
| `not supplied` | A statement has no source, so it came back "could not be checked"; or the findings were not passed on from the claim check: `[GAP: not supplied — source for the cost-savings statement — supply the analysis and check again]` |
| `conflicting` | Two findings give different statuses for the same statement and the claim check did not settle which applies |
| `needs a decision` | Whether the open items are acceptable for the reader. Only the named reviewer decides: `[GAP: needs a decision — whether the 2 open items can stay — your market access review]` |
| `out of date or unclear date` | A source score shows currency was not checked, or the source was flagged superseded or withdrawn |

Wording rules:

- A gap names what is missing for the figure or the item, never a guessed percent.
- "Could not be checked" is never worded as "false" or "wrong".
- On the card the person reads, gaps appear as plain open items; the bracket syntax is
  used inside the draft text or when the person asks for it (TR-H13).
