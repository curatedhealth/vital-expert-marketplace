# Output format: record note

Follows the deliverable, never inside it. Plain language, no rule codes or skill names
(TR-H13). Size it to the stakes (TR-H12). Where it ends up in the final document (an
appendix slide, a footnote, a line in the cover email) is the person's choice.

Every line says where it comes from: stated plainly if seen in this conversation; "as
you told me" (or "per <name>") if the person said it; a gap if not known.

## Internal and quick

Nothing by default. If asked:

```
Drafted with the assistant from your notes.
```

## Leadership or cross-team (short note)

```
How this was made (draft, not yet reviewed)

Built from: <materials, one line, named as the person named them>
AI's part: <plain verbs: drafted the text, summarized X, built the table from Y>
People's part: <only as stated, attributed; or "none yet">
Assumed: <the one to three choices that change the conclusion>
Open: <what is still missing or to be decided, with owner>
Status: <status line from status-line.md>
```

## Leaving the company (full note)

```
Record of how this was made

Work: <title as the person gave it>
For: <reader, e.g. regional payer meeting>

Built from
1. <material, as named; version or date only if given; "summarized" where used in part>
2. ...

Assistant and tools
- Assistant: <as this conversation shows it; model or version only if the host shows it>
- Connectors or tools used for this work: <only those that ran; or "none">

What the AI did
- <part of the work>: <drafted | summarized | translated | restructured | compared figures with your file | suggested wording>
- ...

What people did
- <step, person, date, as you told me>; or "No one else has reviewed this yet."

Checks that ran
- <e.g. "Figures in the text compared with the sales file you shared: no differences left open.">
- Not run: <e.g. "No tool check of claims against their sources.">

Assumed
1. <assumption, whose, why it matters>

Open
1. <gap or decision>; owner: <as the person named them, or "owner to be named">; must be closed before use: <yes | no>

Status: <status line from status-line.md>

Next step: this goes through your <kind of internal process, e.g. market access or
promotional review process> before it is used.
```

Do not add the TRUSTED closing statement to the record note. It belongs to check
outputs only.
