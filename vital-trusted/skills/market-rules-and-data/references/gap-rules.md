# Gap rules applied to market rules and data

> **Where the marker belongs.** Use the `[GAP: …]` marker only inside a drafted deliverable. In notes, open-item lists and explanations, write the gap as a plain sentence ("Still missing: …, from …"). See `trusted-capability-map/references/gap-rules.md`.

Same format and classes as every TRUSTED skill:
`[GAP: <class> — <what is missing> — <what would close it>]`

In the person's draft, required statements usually appear as plain placeholders where
the element belongs (`[Job code — from your approval system]`), because the person will
fill them before review. In notes and check lines, use the gap form. In what the person
reads, prefer the plain question over raw gap syntax (TR-H13).

| Class | Typical case in this skill |
|---|---|
| `not supplied` | The market; the approved label for that market; the PI link; the company name for the reporting line; the person's template |
| `needs a decision` | Where a post about a prescription medicine may appear; whether a reminder exemption applies; the minimum count to show; whether a case story can be used at all; whether a named doctor agreed to be named |
| `not checkable here` | Whether a job code, date or PI version is the current approved one, with no approval-system companion; the full list of statements a market expects, beyond the rules read here |
| `conflicting` | The person names one market but the draft carries another market's approval, reporting route or legal entity |
| `out of date or unclear date` | A PI or label with no date; a "date of preparation" that predates a label change the person mentions |

Wording rules:

- Name the element and the market: "PI link for the UK", not "regulatory information".
- Never hint at a value: no sample job code, no "probably October 2026", no example
  threshold.
- Never write a gap that repeats a personal detail. Name the kind of item, not the
  person.
- A missing element is "not in the draft", not "non-compliant".
