# Primary rules behind this skill

Each rule names its primary source, the date and how it was confirmed. A rule marked
`[CHECK]` has not been confirmed against the primary document and is described as usual
practice, not cited as a requirement (TR-H8). Every rule carries its jurisdiction and is
never applied outside it.

Last reviewed: 20 October 2026. All rules marked Confirmed were read in the official
copy named, on that date, by the author of this skill.

## The rule that governs first

| Id | Rule | Source | Status |
|---|---|---|---|
| M0 | What a piece must carry, and whether it may be used, is decided by the company's own review process for that market, which applies the law, the local industry code and the company's own standards. | The person's company process (TR-H11). | Owner-stated design rule. This skill prepares the draft for that process; it never answers for it. |

The public rules below explain why an element is usually expected. They are a starting
list for the review process, never a complete one, and never a finding that a piece
meets them.

| Id | Rule | Primary source | Scope | Status |

## How to use these rules in output

- In what the person reads, give the reason in plain words: "In the UK, promotional
  material for doctors carries the prescribing information or a link to it, and the
  side-effect reporting line." Cite the clause only if asked.
- Never extend a rule beyond its jurisdiction. M6 to M8 are a UK industry code; they say
  nothing about Switzerland. M14 and M16 are US; they say nothing about the EU.
- A `[CHECK]` element is described as "usually expected; your review process will
  confirm", never as a requirement.
- A list built from these rules is "what is usually expected", never "everything that is
  required". The review process for that market holds the complete list.
