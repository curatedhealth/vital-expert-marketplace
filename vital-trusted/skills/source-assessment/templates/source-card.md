# Output format: source card

What the person reads, one card per source. Plain language, no rule ids or pattern ids
(TR-H13). "What it can carry" and "What it cannot carry" are always present. No tier, no
score, no grade, and never a verdict word (TR-H3). Every card is labeled "not tool-checked".

## Full card (anything leaving the company)

```
Source: <title or description as the source shows it>, <issuer or authors>
Identifier: <DOI, PMID, document number or link as supplied, or "none supplied">

Kind: <e.g. "a company press release", "a preprint", "a peer-reviewed trial publication">
Peer review: <peer reviewed, with the journal and the line that shows it | not peer reviewed, because the source says so or is a kind that never is | status not confirmed: what would confirm it>
Funders and interests: funded by <as disclosed, or "not stated in the source">; <interests, as disclosed, or "not stated in the source">
Fit to your question: <which of population, comparison, outcome, setting match, and which do not>
How strong: <design as the source states it>; <one study | several studies that agree | several that disagree>

Date: <date in full, e.g. "12 March 2026", or "full date not shown">
Currency: <"checked by you on <date>" | "not checked">. The check you can do: <the journal's page for the article and a retraction database | the issuing body's page for a newer version | opening the DOI or PMID to see it matches the title and authors>

Can carry for <reader>: <the narrowest statement it supports, in its own words>
Cannot carry: <what it should not be used to say>

To use it: <what would close the gap, e.g. "the published article", "the event rates", "the 2026 version">
Next step: this goes through <the review named for this deliverable in ../../citation-and-record/references/escalation-packet.md; for payer or health-professional material, your market access or promotional review and your medical review>, as your process names it, before it is used.

Not tool-checked: I read what you supplied. Currency and retraction checks are yours to make.
```

A source the person did not supply or name is never described as existing or attached.
"Data on file" is described only when the person supplied it or said it exists, as
"company data on file (unpublished analysis, <date as given>)"; otherwise it is a gap.
Figures are copied as the source gives them: "62 of 140" stays "62 of 140", never "44%"
or "nearly half" unless the person asks, labeled.

## Short card (board, leadership, internal brief)

```
<Source, date in full>: <kind>; <peer review status>; <funder or maker, if it matters>.
Can carry: <one line>. Cannot carry: <one line>. Currency: <checked by you on <date> | not checked>. Not tool-checked.
```

## One line (quick internal note)

```
<Source> is <kind>, <date in full>; it can be mentioned as <what it can carry>, not as <what it cannot carry>. Not tool-checked.
```

## When only a description of the source was given

Use the card at the size above. Fields come from the description, marked "as you
describe it"; a field the description does not give reads "not seen". Replace the last
line, and add the one-line ask:

```
Not tool-checked: I read your description, not the document. Currency and retraction checks are yours to make.
Can you paste or attach it, so I can read it rather than your description?
```

## When the person asked for a verdict

Open with one sentence that reframes, then the card:

```
I can't tell you whether it is good enough; your <review process> decides that. Here is
what it can and cannot carry for <reader>, so you can decide where to use it.
```

## Closing statement

A card given as a check, at any size including the one-line card, ends the reply with the
closing statement, once, as the last line (`../../claim-assessment/references/statuses.md`).
Only a "Detail for reviewers" section the person asked for comes after it. A reference
list on its own and an explanation do not carry it.
