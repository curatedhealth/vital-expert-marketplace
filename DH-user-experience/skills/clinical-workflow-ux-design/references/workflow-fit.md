# Workflow fit: what the sources say about placing a screen in clinical work

Used by A1. Every rule carries the row it rests on. `UX-` rows are in `ux-usability-research.md`; `CS` rows are in `implementation-research.md`. Rows marked [PAPER] are published methods (DOI in the row); rows marked [WF] were read by a summarizer and are said to be so wherever used.

## 1. Fit is a named construct, separate from priority

| Rule for the skill | Rows |
|---|---|
| Fit with workflows, systems and processes ("Compatibility") is its own construct in the 2022 CFIR, separate from whether the site ranks the product above other work ("Relative Priority"). A1 records fit; priority is the site's. | CS14 [PAPER] |
| CFIR lists constructs and does not state causal relationships between them. Never present a fit finding as a prediction of adoption. | CS3 [PAPER] |
| The 2022 CFIR must be made project specific before use: define each domain's subject in the project's language. In A1 that means the inner setting is the unit where the task happens (for example a ward), the outer setting the system around it. | CS11, CS12 [PAPER] |
| Roles can be mapped to the CFIR roles (for example high-level leaders, implementation leads, deliverers, recipients) and described by need, capability, opportunity and motivation. Use the person's own role names first. | CS18, CS19 [PAPER] |
| Adaptability depends on separating core components (kept) from the adaptable periphery (may change by site). A1 asks the person which screen elements are core. | CS4 [PAPER] |

## 2. Where decision support must sit

| Rule for the skill | Rows |
|---|---|
| For certified health IT, decision support interventions must occur while the user is interacting with the technology (45 CFR 170.315(b)(11)). | UX-US-54 |
| Certified modules must let users give feedback on evidence-based interventions and export it with intervention, action, feedback, user, date and location. A1 notes where in the task that feedback would be given. | UX-US-55 |
| Under FDA's CDS guidance (29 January 2026), basis information should promote usability and avoid information overload, prioritizing the most decision-relevant information and making extra detail available. This is the design principle for "data shown" versus "data available on request". Whether the product is a device is not decided here. | UX-US-64, UX-US-70 |
| FDA does not consider software for a critical, time-sensitive task or decision to meet Criterion 4. If the task the person names is time critical, say so and route the device question to the regulatory owner. | UX-US-66 |

## 3. The screen and its environment

| Rule for the skill | Rows |
|---|---|
| The user interface includes packaging, labeling, training materials, controls, displays, alarms and logic of operation. A1 lists all of these that touch the task, not only the screen. | UX-US-31 |
| Software for mobile platforms must account for screen size and contrast and for varying light and noise (MDR Annex I 17.3). Ask where the task happens: bedside, corridor, home. | UX-EU-16 |
| Measurement, monitoring and display scales must follow ergonomic principles for the intended purpose, users and environment (MDR Annex I 14.6). | UX-EU-15 |
| Devices for lay use must suit lay skills and environment; instructions must be easy for lay persons to understand and apply (MDR Annex I 22.1). | UX-EU-17 |

## 4. Deployment facts that bear on fit

| Rule for the skill | Rows |
|---|---|
| NICE ESF Standard 12: the proposed pathway description covers training and education needs and barriers or enablers to implementation. A1's "step added" includes training the step needs. | CS58 |
| NICE ESF Standard 15: products affected by local factors (for example AI) can be checked in silent mode, observed on local inputs but not used in care decisions, before integration into the pathway. Offer it as an option where the person's product adapts to local data. | CS60 |
| NICE ESF Standard 20: the company must communicate outputs, key features, benefits and limitations, and should describe its end-user training approach. | CS65 |
| The 2025 ONC SAFER Guides are eight self-assessment guides in three groups; the clinical process guides are Patient Identification, CPOE with Decision Support, Test Results Reporting and Follow-Up, and Clinician Communication. A1 names the guide whose practices the task touches, so the deploying site can check its own self-assessment. The CMS measure text still says "all nine" guides and ONC says the 2016 versions apply for the CMS measures. | CS72, CS73, CS74 |
| NHS deployment: DCB0160 applies to organizations that deploy, use, maintain or decommission health IT; NHS Digital states DCB0129 and DCB0160 compliance is mandatory. Both rows are [WF]; say so if used. DCB0160 clause content is not sourced `[GAP]`. | CS70, CS71 [WF] |

## 5. What the sources do not give

- No source gives a time-saving method or benchmark. "The screen saves time" needs the old step named and the person's own measurement (old register rule kept).
- No source sets how many clicks, fields or alerts are acceptable. That is the person's design standard.
- SAFER Guide practice text was not extracted, only titles and grouping (CS73). Quote a practice only from the guide itself `[GAP]`.
